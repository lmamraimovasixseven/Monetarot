Methods and limits

Model: ordered logit on 6 factors, frozen specification; holdout = the last 18 of 89 usable decisions. The 95% block-bootstrap interval for the RMSE ratio (0.780 to 1.335) contains 1, and the Diebold–Mariano test (HLN-corrected) gives p = 0.961, so on 18 holdout decisions the model cannot be distinguished from Always Hold in either direction.

Supplementary measure (exploratory, added after the holdout had been seen; the pre-specified verdict stays RMSE-based): the ranked probability score on the same holdout (lower is better) is 0.154 for the model, 0.194 for Always Hold and 0.159 for the class frequencies of the estimation sample. Simple class frequencies do almost as well as the model, so the six factors add little beyond the base rates of cuts, holds and hikes; most of the gain over Always Hold comes from admitting that cuts and hikes happen.

What the static page does differently

  • Tabs. The four Render tabs (Overview, Drivers and scenario, Evidence, Data and provenance) are spread over the seven steps on the home page and over the Evidence and Data pages.
  • NBK calendar check. Each time it opens, Render queries the calendar source and shows “CACHED DATA” if the source does not answer within 2 s. The static page contacts no external address; the round dates come from config/forecast_rounds.json and are chosen in the browser from today's date.
  • Render time. The line “Cached dashboard render time” belongs to the Streamlit server; a static page has none.
  • Table sorting. Streamlit tables sort when you click a column header; here they are static, in the same row order.
  • Scenario slider. It is recomputed in the browser with the same formulas (ordered logit and the delta method) as src/app.py; a test checks the match to 1e-6.

Limits

The model cannot be told apart from Always Hold

Holdout RMSE ratio 0.995; 95% bootstrap interval 0.780–1.335, Diebold–Mariano test p = 0.961 on 18 decisions. The rule's label changed after one new decision: Effect of the data update (OLD = git tag before-data-update-2026-09-07, NEW = current files): usable decisions 88 → 89; estimation sample 70 → 71 decisions (ending 2024-06-03 → 2024-07-15); holdout 18 → 18 decisions (2024-07-15–2026-09-07 → 2024-09-02–2026-10-27). The holdout RMSE ratio changed from 1.002 to 0.995, so the pre-specified rule's label changed from "does not meet the pre-specified criterion (RMSE ratio not below 1)" to "meets the pre-specified criterion (RMSE ratio below 1)". 95% bootstrap intervals: OLD 0.828 to 1.230, NEW 0.780 to 1.335; both ratios lie inside both intervals, so the change does not show that the model forecasts better or worse than before.

Comparison with class frequencies (RPS, supplementary measure)

RPS: model 0.154, class frequencies 0.159, Always Hold 0.194.

The parameters are unstable

LR test of equal slopes, 2015–2019 against 2020+: p = 0.013 (FAIL).

The holdout is not untouched

The holdout was partly seen in early runs, and there was no preregistration before the analysis (D15); only the forecasts in docs/forecast_log.csv are truly out of sample.

Publication lags are not verified

Real publication lags: UNKNOWN; the model assumes "decision month minus 2". There are no data vintages, so the series backtests use revised data.

A named past failure

The project's first classifiers (logistic regression and random forest on factor levels) predicted the same class for every decision on a test of 16 decisions (2024-10-14 – 2026-09-07); accuracy 0.188 against 0.625 for Always Hold (outputs/legacy/). Lesson: a model without a benchmark and without a check on trending factor levels looks as if it works until it is compared with "nothing changes".

Decision memo (Gate 0)

Decision (awaiting confirmation by a person): A treasurer or portfolio manager holding tenge government bonds decides, before the NBK meeting on 4 December 2026, whether to extend or shorten duration.

Usefulness Test

  • Without you: the user looks at the current rate and the NBK's statements and by default assumes that the rate will not change (Always Hold). That is our benchmark.
  • Change: the model gives the probabilities of a cut, a hold and a hike and turns them into a duration action through an explicit loss function.
  • Cost of error: extending duration when no cut comes (loss: 1, in notional units); not extending when a cut comes (forgone gain: 1, in notional units). The values are a user assumption.
  • Who benefits: holders of tenge government bonds (bank treasuries, portfolio managers); they see not only the probability but also the threshold at which acting is worthwhile.

Threshold from the loss function

Extend if P(cut) > p* = L_false / (L_false + L_miss) = 0.500.

Now (probabilities as of the decision of 2026-10-27) P(cut) = 0.387, so the binary rule says: do not extend.
