# Update Drill: чек-лист на 45 минут

Тренировка: `python run.py drill --card <карточка>` имитирует карточку на временной копии (репозиторий не меняется), прогоняет `python run.py update`, сравнивает до и после и печатает черновик заметки на 100 слов с пустыми местами `[ВАША ОЦЕНКА]`. `--light` прогоняет только нужные шаги (секунды). В день Drill с настоящими данными действуйте по `docs/RUNBOOK_data_update.md`.

## Общий порядок (для любой карточки)

| Минуты | Шаг |
|---|---|
| 0–5 | Прочитать карточку; назвать, какой файл и какое число она затрагивает; `git status` чистый; `git tag before-drill-<дата>`. |
| 5–15 | Внести изменение по RUNBOOK (только добавление строк в `data/raw/`; пересмотр — новая D-запись, а не правка строки). |
| 15–30 | `python run.py update`; затем `python -m pytest -q -k "not check_01"` и `python run.py check`. |
| 30–38 | `python run.py compare` и сравнение: вердикт RMSE, вероятности, порог, флаги экрана, вердикты прогноза рядов. |
| 38–45 | Заметка на 100 слов (черновик из `drill`), человеческая оценка вместо `[ВАША ОЦЕНКА]`, коммит. |

## Пять карточек

| Карточка | Что происходит | Что проверить | Чего не делать |
|---|---|---|---|
| `revision` — ревизия данных | издатель пересмотрел уже опубликованный месяц | append-only guard падает: пересмотр нельзя внести правкой строки; записать в `docs/deviations.md` и `docs/manual_steps_found.md`, решить с преподавателем | молча перезаписать строку |
| `release` — новый релиз | вышел новый месяц фактора | `python run.py needs <дата решения>`; добавить строку; вероятности и флаги до/после | подставить значение «по памяти» |
| `shock` — структурный шок | резкий скачок | экран скачков: новый флаг, тип эпизода, попадает ли в последнюю оценку; предупреждение на сайте | удалить или сгладить точку |
| `broken_source` — сломанный источник | файл источника повреждён | обновление останавливается с понятной ошибкой (файл и строка), откат: копия удаляется, репозиторий не меняется | пропустить ряд молча |
| `question` — новый вопрос от лица, принимающего решение | например, «а если упущенное снижение вдвое дороже?» | изменить потери в `config/decision_losses.json`, порог и действие до/после | менять модель под вопрос |
