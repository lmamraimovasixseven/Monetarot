Project rules (apply to every task):
1. Never fabricate numbers, URLs, series identifiers, retrieval dates, references or DOIs. If something is unknown, write "UNKNOWN" and list it in TODO_HUMAN.md.
2. data/raw is append-only (rule 12): never edit or delete an existing row there. All cleaning happens in code.
3. Estimation and serving are separate. src/app.* must never call .fit(), OLS, or any regression. It only reads data/processed and model/artifact.json.
4. No hard-coded results anywhere in src/app.*. Every number on screen is read from data or the artifact.
5. Fix every random seed and record it in the artifact.
6. Report failures honestly. A model that does not beat the benchmark is an acceptable result; never tune on the last 20% holdout.
7. Every figure/table used in the technical note is generated by code into outputs/.
8. No credentials, tokens, or personal data in the repo.
9. After each task, run the tests and tell me exactly which checks pass and which fail. Do not claim success without running the command.
10. No hard-coded counts or dates in tests, templates or generated text. Tests assert relations computed from the data and the artifact (for example "holdout = ceil(0.2 x usable decisions)", "usable decisions = calendar dates whose reference months exist in every factor file"), never literals such as 89 or 18. Hand-written docs put such counts in generated blocks filled by `python run.py facts`.
11. Every data update follows `docs/RUNBOOK_data_update.md` (tag the old version, `python run.py needs`, append, data -> model -> robust -> report -> facts -> check -> tests, `python run.py compare`, record in `docs/manual_steps_found.md` and `docs/deviations.md`).
12. data/raw, `config/nbk_decision_dates.csv`, `docs/nbk_announcement_dates.csv` and `docs/forecast_log.csv` are append-only: new lines at the end only. `tests/test_data_contract.py` compares them with git HEAD and fails if a committed row changed or disappeared. Flagged outliers (`outputs/data_anomalies.md`) are never altered.
13. Forecasts are logged before decisions: run `python run.py forecast-log` before each NBK decision and commit and push the log the same day. The main specification is frozen; candidates are explored and promoted only under `docs/development_plan.md`.
14. Wording of results: a holdout RMSE ratio below 1 "meets the pre-specified criterion"; never write that the model is better unless the bootstrap interval and the Diebold-Mariano test separate it from the benchmark.
