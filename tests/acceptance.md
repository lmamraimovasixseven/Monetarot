# Приёмные проверки

Команда: `python run.py acceptance` (свежая копия рабочего дерева) или `python run.py acceptance --clone` (только закоммиченное). Реализация: `src/acceptance.py`; статусы PASS, FAIL, PENDING DATA (код проверен, реальных данных нет), RESERVED.

| ID | Проверка | Как проверяется |
|---|---|---|
| A01 | Чистая машина, офлайн, одна команда | `python run.py update` на копии проекта завершается с кодом 0; сеть не используется |
| A02 | Cutoff-дата: значение после cutoff не двигает вывод | прогноз naive, AR(1), ARIMA с искажёнными данными после cutoff совпадает |
| A03 | Тот же код на курсе USD/KZT без правок | ряд `usd_kzt` идёт тем же путём `load_series → backtest → forecast`; PENDING DATA, пока файл — шаблон |
| A04 | Сезонные ряды сравниваются с seasonal naive | бенчмарк сезонных рядов в `forecast_desk` = `seasonal_naive` |
| A05 | Журнал прогнозов закоммичен раньше релиза | первый коммит каждой строки `docs/forecast_log.csv` раньше даты решения (`git log -S`) |
| A06 | Смена одной настройки вживую с объяснением | соотношение потерь 1 → 3 меняет порог 0.5 → 0.25 = 1/(1+3) |
| A07 | Трассировка числа сайта через журнал, код и модель | `python run.py trace n:rmse_ratio` согласован |
| A08 | prereg не менялся после заморозки | `python run.py prereg-check` |
| A09 | Сайт на 360 px и в бюджете скорости | тесты `tests/test_site.py`: viewport и ширины, загрузка < 3 с, alt, без CDN, без заглушек |
| A10 | Чистый клон проходит все тесты | `python -m pytest -q -k "not check_01"` на копии |
